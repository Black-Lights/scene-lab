# v0.3 architecture: free scenes on a toolkit

Status: FINAL for building, 15 November 2026 (second version, after an independent review by five reviewers; the
fifth, on runtime risk, arrived while the core was being built and is folded in as section 6.8. The record of what
the review changed is in section 9). Wish list: what the v0.2 engine could not express, as found while making an
earlier 3D video. Rules: FEEDBACK.md F-001 to F-012, above all F-010
(the engine is for any topic) and F-011 (2D or 3D per scene, whichever explains better).

## 0. What changes

A video may carry its own scene code: React components in `videos/<slug>/scenes/`, running on the engine as a
runtime (narration, timing, captions, chapters, cuts, assets, render) and on a toolkit, `src/kit`, imported as
`@kit`. The spec stays the script: narration, order, and every time that depends on a spoken word. Old specs render
unchanged.

1. A scene is a pure function of time, its spec fields, the theme and its assets. No clock, no randomness.
2. Every time that depends on narration is declared in the spec (`cue`), where make.py resolves and checks it.
   Scene code never holds a cue word.
3. Every name that crosses from spec to code (a track, a place, a beat, an asset) is declared in the spec and
   checked at build time. A wrong name is an error before the render, never a silent default in it.
4. The kit is topic-free and treats 2D and 3D alike: the same world, camera, places, labels and state for both.
5. Small pieces that compose. Scene code is ordinary React, SVG and react-three-fiber; raw three geometry is
   first class.

## 1. Conventions (frozen: every author follows these, no exceptions)

- **Time.** Seconds everywhere, never frames. Scene time `t`: 0 is the scene's start on the narration timeline (the
  voice starts at 0.35 s). A scene is on screen from about -0.7 s (cut in) to dur + 0.3 s, so everything must be
  defined for t < 0 and t > dur. World time `T = scene.start + t` is the base for state and camera.
- **Time words.** `at` is a time in seconds and nothing else. `over` is a duration. `cue` is a phrase of the scene's
  `say` and exists only in spec JSON (make.py turns it into `at`). `until` is a second phrase that ends a change
  (make.py turns it into `over`). In code, `t` is the first argument of every time helper.
- **Position words.** `pos` is a position, `size` a box, `on` a reference to a named place, `frame` the places a
  shot fits, `target` what a camera looks at. A position is never called `at`.
- **3D space.** Right-handed, Y up, ground at y = 0. A world unit has no physical meaning; a video states its own
  scale. `pos` of a kit shape and of a place is the centre of its base (it stands on y = pos[1]); `size` is
  [x width, y height, z depth]. three's own `position` (the box centre) is for raw meshes only.
- **2D space.** Board units are layout pixels at zoom 1, origin top left, y down. A 2D place is
  `{ pos: [x, y], size: [w, h] }` with `pos` its top-left corner.
- **Data to world.** 2D data (x, y) maps to world (x, height, -y), so a top view shows data unmirrored.
- **Angles.** Degrees in the spec and in kit props (`az`, `el`, `fov`, `orbit`, `rot`). `az` = 0 puts the camera on
  +Z looking at -Z and grows towards +X; `el` = 0 is the horizon, 90 looks straight down; `fov` is vertical,
  default 34. No kit prop is named `rotation`. (The old `stage3d` template keeps radians; it is legacy.)
- **Colour.** Props and data spell `color`. A colour input is a hex string, a paint name, a role name (a, b, c,
  warn) or a theme token (ink, ink2, back, line, surface, bg), resolved by `paint(th, ref)`. An unknown name is an
  error. The kit holds no hex literal and no topic word.
- **Rendering colour.** The 3D canvas is `flat` (no tone mapping) with sRGB output, so palette colours match the
  2D layer.
- **Layout space.** All HTML, SVG and overlay coordinates are pixels in 1920x1080, whatever the render scale. The
  content area is `AREA` (src/theme.ts). Type sizes come from `TYPE = { s: 30, m: 40, l: 54 }`; nothing on screen
  is smaller than 28 px.
- **Names.** Ids, track keys and place names are lower-case dot paths (`gate.open`, `cell.cold.3`). One id space
  per world: a place name is also the id used for focus and labels. `visual.component` = file name = the default
  export, PascalCase. Reserved keys of a free visual: type, component, world, title, tracks, places, beats, set,
  shots, labels, assets, sfx, props.
- **Easing.** `ease` is a name: enter, exit, move, linear (src/motion.ts). Default durations come from `DUR`:
  camera 1.3, numbers and shapes 0.9, colour and focus 0.25, entrance 0.5. No springs, nothing that loops for
  decoration.
- **Where data lives.** Anything timed by narration, state changes, shots, labels and asset requests: spec.json.
  Geometry and layout: `videos/<slug>/scenes/`. Large data: `videos/<slug>/data/*.json`, imported by scene code.
  Text shown on screen (code, messages, tables): the spec or a data file, never a string inside TSX.
- **Loading.** Assets are declared in the spec and loaded by the engine before a scene mounts (the preload gate,
  section 6.6). Scene and kit code read them synchronously with `useAsset`. No loader, no Suspense, no
  `delayRender` and no `fetch` in scene or kit components.
- **three objects.** Mutated during render or in `useLayoutEffect`, never in `useEffect`. Colours enter three as
  hex strings or a `THREE.Color` built from hex. Dimming is a colour mix toward the ground colour, never opacity;
  entrances move or scale. No time helper may return NaN.
- **Ownership.** One owner per file. make.py, custom.py, the barrel and the core kit files are edited by the core
  author only. No new npm or pip package without asking the lead.

## 2. The spec

```json
{ "worlds": {
    "hub": { "component": "Hub",
             "tracks": { "gate": 0, "lamp": "ink2", "focus": null, "cell.*": "surface" },
             "places": { "bench": { "pos": [0, 0, 0], "size": [4, 1, 2] } },
             "assets": { "arm": { "q": "robot arm", "kind": "model", "pick": 2 } },
             "props": { "rows": 3 } } },
  "scenes": [
    { "say": "The gate opens only when the bench is clear.",
      "visual": { "type": "world", "world": "hub",
                  "shots": [ { "frame": ["bench"], "az": 35, "el": 22, "cue": "bench" } ],
                  "set": [ { "key": "gate", "to": 1, "cue": "opens", "over": 0.8 } ],
                  "labels": [ { "on": "bench", "text": "Test bench", "cue": "bench" } ],
                  "beats": { "clear": "clear" } } } ] }
```

- **World.** Declared once under `worlds`: its component, the initial value of every state track, its named
  places, its assets and free `props`. A scene of it is `{"type": "world", "world": "<id>"}`. Adjacent scenes of
  one world have no cut. A track family is declared with a star (`"cell.*"`).
- **Free scene.** `{"type": "custom", "component": "Name"}`. It may declare `tracks` and `places` in its own visual
  and use the same blocks; it is a world of one scene.
- **Blocks** any free or world visual may hold, each its own timeline for cue matching:
  - `beats`: `{ "name": "cue words" }`, also `{ "name": { "cue": "...", "nth": 2 } }` or a number of seconds.
  - `set`: `[ { "key" | "keys": [...], "to": value, "cue" | "at", "over" | "until", "ease", "stagger" } ]`. A key
    may be a family (`"cell.cold.*"`). An entry without `cue` and `at` is the state at the scene's start.
  - `shots`: camera moves (section 6.3). `labels`: labels as data (section 6.5).
  - `assets`: `{ name: request or file }` (section 5). `sfx`: sound effects (section 5).
- **Cue grammar** (free and world visuals): letters and digits only; a whole-word match wins over a prefix match;
  inside one list each cue is looked for after the previous one, then from the start; `"nth": 2` picks the second
  time the words are spoken; a cue spoken more than once without `nth` gets a warning; a time is the word's start
  minus 0.12 s. Old templates keep their document-order rule.
- **Direction** (added 18 November 2026, F-015; direction.py). The spec carries the director's record at its top
  level: `"direction": { "audience", "form": "2d" | "3d" | "mixed", "why", "limits", "asked" }`. `audience`, `form`
  and `why` (one or two lines) are required in the block and any other key is an error; a spec without the block
  still renders and gets the warning `not directed`. `limits` is a closed list of tokens for what the user stated:
  `2d-only`, `no-blender`, `no-stock-pictures`, `templates-only`, `no-templates`, `stock-look`. make.py holds the
  video to them and to its `form` before anything is synthesized or rendered, under every flag: each violation is
  an error that names the scene, and the run exits with code 1. Whether a scene draws in 3D or shows a Blender
  render is read from its scene code (following relative imports), its assets and the files' own metadata, never
  from a declaration; the kit's 3D parts count under any local name (`Stage as X`, `Kit.Stage`). As a backstop, a
  video held to 2D carries `only2d` in its props, and the kit's canvas then refuses to draw: a `<Stage>` the text
  could not see becomes a scene error, and `limits_held` drops `2d-only`. `asked` holds the wishes no build can check; the report prints them back as `check_by_eye`,
  beside `direction: { form, limits_held }`. Four warnings do not stop a run (folders whose names start with `_`
  get none): `not directed`, `look` (a stock theme with no ground or ink of its own), `sameness` (one template
  family in three scenes in a row, or in more than a third of a video of eight scenes or more) and `all templates`
  (longer than 2:00 with no scene code). `--design <file>` renders a run in another look into `out/look-<name>/`
  and leaves the spec alone. After a full render without scene errors make.py writes the video's row (date,
  minutes, form, look, chapters, limits) into docs/made.md, the ledger a session reads before it directs the next
  video: newest first, one row per video, at most 45 rows. What a session does with all of this is SPEC.md part 0.

## 3. Build pipeline (make.py and custom.py; the core author owns both)

- **Entry.** custom.py writes `build/entry.tsx`: one `import()` per scene file inside try/catch (a scene file that
  throws while it loads becomes one reported card, not a dead video), then `registerRoot`. A video without
  `scenes/` keeps `src/index.ts`. Video folders live under the repo root.
- **Lint, blocking** (scene files; a line with `deterministic-ok` is exempt): Math.random, Date.now, new Date,
  performance.now, timers, requestAnimationFrame, `useFrame`, THREE.Clock, `useCurrentFrame`, `<Sequence`,
  `<Series`, `<Loop`, `<Freeze`, `spring(`, `useEffect(`, `<Suspense`, `delayRender`, `useLoader(`, `TextureLoader`,
  `GLTFLoader`, `fetch(`. Warning only:
  `interpolate(`, `fps`, CSS `transition` and `animation` keys. Each message names the replacement.
- **Type check.** `tsc --noEmit --incremental` on every run (about 5 s). Errors in the video's own files block;
  errors elsewhere are one warning.
- **Validation** of the kit's blocks in every free and world visual and in `worlds`: known keys only (with the
  closest name as a hint), value types, `set` keys against the declared tracks, `frame`, `on`, `target` and focus
  ids against the declared places, a `cue` beside a non-numeric `at`, `az` or `el` that looks like radians.
- **Report.** The JSON report gains `cues` (one line per timed entry of every free scene: scene, block, key, cue,
  resolved seconds, "match 1 of 2"), `errors` (lint, types, a scene that fell back at render), and
  `placeholders` (assets or shots that could not be made).
- **Error channel.** Kit code and the scene error boundary write `console.error("[kit] scene <n> <component>:
  <message>")`. make.py reads Remotion's output, lifts every `[kit]` line into the report, and exits with code 1
  after a full render in which any scene fell back.
- **Bundle cache.** `remotion bundle` into `build/bundle-<hash of src, scenes, package-lock, remotion.config>`;
  changed files of `build/public` are mirrored into the bundle before each render or still. An edit of the spec
  alone skips the bundle.
- **Sound outside the picture.** Remotion renders muted; the final ffmpeg step muxes the sound. A raw render is
  kept as `build/render-<mode>-<key>.mp4` (key: props without sound, code hash, the public files the props name,
  mode) and reused when nothing visible changed, so a sound change costs a mix and a remux.
- **Looking.** `--strip 3,7,12` (one bundle; samples every timed entry at its middle and just after its end);
  `--still N@t` writes one 1920x1080 PNG of scene N at t seconds (style frames, judging type at full size).
- **Colour and load on the machine.** Remotion renders with `--color-space=bt709`, and every ffmpeg encode
  (make.py, page.py, clips) carries BT.709 tags and yuv420p; until now files were untagged and players decoded
  them with the wrong matrix. `--gl=angle` always for a video with scene code; `--concurrency=4` for `--master`
  when a scene has a 3D stage (a 6 GB card); a lock file per video folder for the length of a run.
- **Hooks** (fixed signatures; the bodies belong to work package C):
  - `assets.resolve_assets(node, vdir, pub, cache, used, warns, ctx)`: every `assets` dict in a visual or a world
    has its requests replaced by `{ src, kind, credit, ... }`.
  - `sound.mix(spec, scenes, narration, sr, total, vdir, pub, used, warns, ctx) -> file name in pub, or None`.

## 4. Runtime (src/custom.tsx, src/Explainer.tsx; core)

- `registerScenes`, the registry, `SceneContext` (`{ scene, index, scenes, words, dur }` for every scene),
  `VideoContext` (`{ worlds }`), the template for `custom` and `world` scenes.
- The error boundary judges every frame on its own (it clears its error when the frame changes), draws the
  plain card, and logs through the error channel.
- A world scene takes its component from `worlds[id].component`.
- The chrome (the chapter bar with its name, the captions) is a layer above every scene, drawn with a halo of
  the ground colour. The scenes are one isolated layer under it, so nothing in scene code, a 3D canvas included,
  can cover the chrome. (Added after the check of 15 November 2026.)

## 5. Assets and sound (work package C)

- Requests: `{ "q": "...", "kind": "photo|illustration|vector|video|model|hdri|sound|music", "pick": n }`, a
  file path, or `{ "id": "provider:id" }`. A lock file kept in git, `videos/<slug>/assets.lock.json`, records
  provider, id, sha1 and licence per request; a locked request is fetched by id and never searched again.
- Models are glTF folders in `build/public/assets/<id>/` (Poly Haven: the .gltf plus its `include` files;
  Sketchfab: unzipped). No conversion through Blender. HDRIs are the 1k .hdr. Clips are conformed to 30 fps,
  scaled to the size they are shown at, without sound.
- Sound: top-level `"music": { "q" | "file" | "id", "gain": dB, "duck": dB }`; `"sfx": [ { "cue", "sound",
  "gain", "offset" } ]` inside a visual. Narration is the reference: one static gain to -16 LUFS. The bed is
  levelled to it and ducked by an envelope computed from the known voice intervals (no compressor). Effects are
  trimmed, levelled and placed at `scene.start + at + offset`. With a mix, the final encode uses a limiter in
  place of the dynamic loudness filter. The report prints the levels. Music is never chosen by default: without a
  pick there is no bed. `--assets` writes an HTML page with players for sound requests, since a contact sheet
  cannot be heard. ND licences are rejected (docs/asset-sources.md).

## 6. The kit (`src/kit`, one barrel, imported as `@kit`)

Scene components receive `{ v, dur, scene }` and use hooks. Everything below is exported from `@kit`, together
with `useTheme`, `AREA`, `EASE`, `DUR`, `prog`, `lerp`, `clamp01`, `Glyph`, `DrawPath`, `HArrow`, `SceneTitle`,
`fitSize`.

### 6.1 Time, colour, type (core: time.ts, paint.ts, type.ts)

```ts
useClock(): number                                 // scene seconds
useScene(): { scene, index, scenes, words, dur }
useBeat(name, fallback?): number                   // seconds; throws when the scene declares no such beat
useBeats(): Record<string, number>
tween(t, from, keys): value                        // keys: [{ at, to, over?, ease? }]; numbers, vectors, hex colours
mix(a, b, p), mixColour(a, b, p), step(t, at), prog(t, at, dur, ease?)
useWords(), wordAt(words, phrase, nth?)            // for text that follows the voice, never for timing a motion
paint(th, ref): string, usePaint(): (ref) => string
TYPE, textStyle(th, 's' | 'm' | 'l'), dataStyle(th, size)   // dataStyle: tabular figures in the data face
```

`mixColour`, `mix` and `tween` take hex colours only: a paint, role or token name throws and names `paint(th, ref)`
and `usePaint()`. A length of 0, or one that is not a number, is an instant step; a start that is not a number
never comes. (Added after the check of 15 November 2026.)

### 6.2 World state (core: world.ts)

```ts
const w = useWorld();          // also in a free scene with its own "tracks"
w.id, w.T, w.t                 // world id; world time; scene time
w.run                          // seconds since this unbroken run of the world began (for things that keep running)
w.props, w.places, w.asset(name)
w.num(key), w.vec(key), w.color(key), w.get(key)       // the value now; plain functions, usable in loops
w.state(key) -> { from, to, p }                        // for values that cannot be mixed: cross-fade with p
w.dim(id) -> 1 when `id` is in focus or nothing is, 0.3 otherwise, cross-faded; ids match by dot prefix
```

All `set` entries of every scene of the world sit on one timeline at `scene.start + at`. A value starts at its
declared initial value and follows the entries in time order; each entry moves it from wherever it is. Because
the timeline is the video's, a change that starts at the end of one scene finishes in the next, and the seam
between two adjacent scenes of a world is exact. Reading an undeclared track throws. `focus` is the one reserved
track (an id, a list of ids, or null).

### 6.3 Camera (core: camera.ts, pure functions, no React)

```ts
type Shot = { at?, over?, ease?,               // when the move starts, how long it takes
  frame?: string | string[],                   // places to fit into the content area
  target?: string | Vec3,                      // what to look at (default: the centre of `frame`)
  pos?: Vec3,                                  // an explicit camera position, in place of az / el / dist
  preset?: 'establish' | 'top' | 'side' | 'front' | 'low' | 'close',   // a table of az, el, dist
  az?, el?, dist?, fov?,                       // dist multiplies the fitted distance
  pad?: number,                                // extra room around the framed places, as a fraction
  fit?: 'area' | 'full' | [x, y, w, h],        // where on the frame the subject sits; default the content area
  orbit?: number }                             // degrees per second while the shot holds; opt-in, costs file size
```

- A pose is `{ target, az, el, dist, fov, shift }`. Moves interpolate around the target, azimuth the shorter way.
- The camera runs on world time over the shots of every scene of the world. Rules: a shot without `at` in a scene
  that directly follows a scene of the same world is a move that starts at t = 0; in any other scene it is the
  opening pose (a cut); a scene with no shots holds the pose it inherits, and the first scene of a world opens on
  `establish` over all places; every move starts from the pose at that instant.
- `fit` moves the principal point, so the subject is centred in the content area between the chapter bar and the
  captions; `project(pose, point)` uses the same matrix.
- The 2D board has the same Shot with `frame`, `dist` (as zoom), `pad`, `fit`; its pose is `{ x, y, zoom }`.

### 6.4 The two stages (core: stage.tsx, board.tsx)

```tsx
<Stage v={v} places={more} rect={[x, y, w, h]} light="studio" ground="shadow" fog={false} overlay={<>...</>}>
  {/* react-three-fiber children: the world */}
</Stage>

<Board v={v} places={more} rect={[x, y, w, h]} overlay={<>...</>}>
  {/* HTML and SVG children positioned in board units */}
</Board>
```

- Both read `shots` and `labels` from `v`, take their places from the world (plus `places`), run the camera on
  world time, and give `useStage()`: `{ kind, pose, project(pointOrPlace), places, rect }` to the overlay and to
  the children. The stage's context is computed outside the canvas and provided above it, so the overlay and the
  3D children read the same one. One 3D `Stage` per scene (each is a WebGL context, and a filmstrip mounts a scene
  eight times); a `Board` and a `Stage` may share a scene.
- `Stage`: the kit's own canvas host (section 6.8) in the rect, `flat`, shadows, `light`: studio, day or flat;
  `ground`: shadow (a shadow-only plane over a transparent canvas, so the ground is the page's own colour),
  solid, none, or `{ color, size }`; near and far from the pose and the bounds of the places.
- `Board`: a canvas of any extent that the camera pans and zooms; text stays vector. Its children scale with the
  zoom; `<KeepSize pos>` keeps a name or a number at its size on screen. A second `Stage` mounted in one scene
  turns the scene into its error card. (The last two sentences: added after the check of 15 November 2026.)
- `overlay` is HTML above the stage in layout pixels. `Pin` and `Label` belong there; using them among the 3D
  children throws a clear error.

### 6.5 Overlay (core: overlay.tsx; label layout: work package A1)

```tsx
<Pin on="bench" side="right" dx={12} dy={0}>{children}</Pin>       // any HTML at a place or a `pos`
<Label on="bench" text="Test bench" sub="two probes" size="m" at={beat} until={end} leader />
<Counter value={w.num('margin')} decimals={2} unit="deg" size="l" />
labels (data): [{ on | pos, text, sub, size, side, cue, until, leader, id }]
```

Labels given as data are laid out without overlaps. The layout is solved once per shot at its settled pose, over
four sides, and interpolated between two shots with the camera's own progress, so labels never swap sides in a
single frame. A label with no free side is hidden for that shot.

### 6.6 Assets at render time (core: preload.ts; loaders for models and HDRIs: work package C)

make.py lists every asset of a visual and of its world in the props. Before the engine mounts a scene it loads
them all, together with the video's fonts: one cache per URL, the frame held by a handle taken in a layout
effect, a failed load turned into the scene's card and a report line. `useAsset(name)` is then synchronous and
returns `{ src, kind, credit, data }` (a decoded image, a parsed glTF, HDR data). A model is cloned per mount.
Text drawn into a texture is safe because the fonts are part of the same gate. Loaders register by kind, so
work package C adds models and HDRIs without touching the core.

### 6.8 Runtime rules (core; from the fifth review, which read the installed library code)

- **Canvas host** (`canvas.tsx`). react-three-fiber's `Canvas` with the frame loop off, a fixed 1920x1080 layout
  size, `flat`, the explicit `PCFShadowMap` type, `dpr` equal to the render scale clamped to 0.5..2 (0.5 inside a
  filmstrip cell), and a `Draw` component as its LAST child. `Draw` advances the canvas once per frame and
  releases a per-frame `delayRender` handle that was taken in a layout effect, on every frame including the
  first. Being last, it draws after every effect of the scene. `@remotion/three`'s `ThreeCanvas` draws from its
  first child and only when the frame number changes, which is why v0.2 filmstrips showed blank textures; the kit
  does not use it.
- **Errors out of the canvas.** react-three-fiber dispatches every error it catches as a global error event, and
  Remotion aborts a render on any such event. So a boundary inside the canvas records the error object and hands
  it to the DOM side, which draws the card, and `src/custom.tsx` installs one window `error` listener that cancels
  exactly the recorded errors. A lost WebGL context and a shader error become the same kind of error. The stage
  throws on a camera pose that is not finite.
- **World runs.** Consecutive scenes of one world are one mount: Explainer groups them into one Sequence, and a
  wrapper gives every frame the scene it belongs to (its words, beats and clock). The WebGL context, the compiled
  shaders and the geometry survive the boundary. When another scene sits between two views of a world, the world
  mounts again; heavy geometry is cached at module level.
- **Light and colour.** The studio rig is normalised so that an up-facing matte surface shows its palette colour
  exactly (directional intensity times cosine, plus ambient, sums to pi). A smoke scene checks that the top of a
  white slab reads #FFFFFF within 2 levels in a PNG still. Unlit pictures, glow and text use `toneMapped={false}`
  and sRGB textures. An HDRI is an environment map on metal and glass only, never the scene's light, except in
  an opt-in `hdri` look that is documented as not colour-true.
- **Draw order.** Ground -1, opaque 0, glass 10. Glass is alpha blended with `depthWrite` off and no transmission;
  one glass layer between the camera and the content.
- **Shadows and depth.** The shadow camera is fitted once per world to the union of the places on a 4096 map
  (refitted for a very close shot, snapped to the texel grid); near and far follow the pose and the world bounds.
- **Instances.** An instanced mesh is keyed by its count, is never frustum-culled, has a white base colour, and
  gets all matrices and colours written in `useLayoutEffect` every frame from the first frame on.
- **Media time.** `Clip` shows media frame `n = clamp(floor(t * mediaFps), 0, frames - 1)`, sampled mid-frame
  inside `Freeze`, so a clip neither runs ahead during the cut in nor changes speed in the 60 fps master.
- **One engine.** `remotion.config.ts` builds its aliases from the real path of the repo root and pins `three`,
  `@react-three/fiber` and `@remotion/three` to the root copies; `src/custom.tsx` throws if it is loaded twice.
  A component inside the canvas of `videos/_kit_core` compares the theme, the clock and the scene it reads with
  the values outside, so a library upgrade that breaks the context bridge fails the smoke test.

## 7. Building it

1. **Core** (two authors, files disjoint): Python (make.py, custom.py, the hooks as stubs) and TypeScript
   (custom.tsx, Explainer.tsx, the core kit files, stub files for every work-package module so the barrel
   compiles). Demos: `videos/_kit_core` (a free 2D scene with beats and tracks), `videos/_kit_world` (a 3D world
   in scenes 1, 2 and 4 with another scene between: state carries over, the camera continues, a thing dims),
   `videos/_kit_board` (the same on a 2D board), `videos/_kit_errors` (a throw in a 2D scene, inside a stage's
   children, in a sibling after the stage on the first frame, at t > 1 s, and at the top level of a scene file:
   the preview must finish, show five cards and list five errors). Then an independent check against this
   document.
2. **Work packages** A1, A2, B, C, H, G in parallel. Each owns its files and its demo folders, verifies with
   `--strip` (one full preview at a time on one GPU), and writes `docs/kit/<area>.md` with its demo as the worked
   example. Demos are shots from unrelated topics, never the first case study. The plan named seven
   (a block of cells, a flow, a cycle, a crowd, series on a board, a ledger, media); the demos that were built are
   the `_kit_*` folders that docs/kit/README.md lists.
3. **Review** by independent reviewers against this document, the wish list and F-010; fixes; the kit's
   pages in `docs/kit/` (a core page short enough to read for every video, and one page per area); SPEC.md;
   CLAUDE.md; smoke tests `_demo`, `_compat`, `_kit_*`.

## 8. Deferred, with the reason

- Blender shots (a render bridge and a `Backplate`): nothing on the wish list needs them and they are the most
  expensive part. Build the bridge when a treatment asks for a hero shot; the design to start from: Blender
  renders stills for per-frame states baked by the kit's own camera code, cached by state, assembled by ffmpeg,
  with places projected by the kit so labels work unchanged.
- Orthographic stage, a camera that follows a moving thing or runs a spline through waypoints, depth of field in
  three (the 3D library), `usePhase` (the integral of a changing rate), saving and reloading world state, drawing one world
  twice in two states, rendering a run of world scenes as one Sequence, an AST-based lint, `--verify` (random
  access check), size-driven splitting in page.py, the `texture` asset kind, removal of `stage3d`.

## 9. What the review changed (so the reasons are not lost)

| Finding | Change |
|---|---|
| `at` meant both a time and a position; a label's cue was silently skipped | `at` is seconds only; `pos` and `on` for positions |
| State and camera were per scene, so a move across a seam jumped | one world timeline (`scene.start + t`) |
| Names crossed from spec to code as free strings with quiet defaults | worlds declared in the spec; build-time validation; throws in the kit |
| Hooks per key could not be used for 45 cells | `useWorld()` returns plain reader functions; track families |
| Two cue matchers (make.py and `useWord`) | beats only; `useWord` removed |
| 2D was second class (five small pieces, no stage) | `Board` with the same model; chart and 2D parts |
| The kit was one video's wish list turned into parts | round shapes, streams, seeded randomness; demos from other topics |
| The camera and stage were on every author's path but owned by one of seven | camera, both stages, overlay and loader are core |
| The fallback card was reported only as pixels | error channel into the JSON report; exit code |
| Sound went through the picture render | muted render, mux, render cache |
| Blender was a second scene language and the costliest part | deferred, with a cheaper design recorded |
| Kit names that were one line of react-three-fiber | Slab, Tube, Instances, Explode, flowS, ramp, Reveal dropped |
| An error inside the 3D canvas still aborted the render | in-canvas boundary, a filter on the global error event, `_kit_errors` |
| Loaders that commit after the draw left filmstrip cells blank | a preload gate before a scene mounts; synchronous `useAsset` |
| The library's canvas draws before later effects have run | the kit's own canvas host, which draws last |
| A world remounted at every scene boundary (a new WebGL context each time, in every render tab) | one mount per run of world scenes |
| Renders were untagged, so players decoded colours with the wrong matrix | BT.709 on the render and on every encode |
| No budget for WebGL contexts and GPU memory at 4K | one stage per scene, dpr from the render scale, 4 tabs for a 4K render with 3D |

### After the independent check of 15 November 2026

Three checkers examined the finished core. What they found, and what changed:

| Found | Change |
|---|---|
| A 3D canvas could draw over the chapter bar and the captions | the chrome is its own layer above every scene, with a halo |
| Names on a board shrank below the smallest type size when the camera zoomed out | `KeepSize` |
| A colour name passed through the mixing functions and reached CSS as a web colour | hex only; a name throws |
| Two stages in one scene meant two WebGL contexts | the second one is the scene's error card |
| A helper file outside scenes/, an edited local picture and the folder of a .gltf escaped the cache keys | the bundle hash follows relative imports; a local file is keyed by its content; a .gltf brings only the files it names |
| Two runs on one video folder could delete each other's bundle | a lock file per video folder |
| The 1080p file and the page parts lacked two of the three colour tags | BT.709 on every encode, checked with ffprobe |
| The 4K render of a 3D scene had never been measured | 16 November: 7.4 to 9.3 s of render per second of video with 4 tabs, 728 MiB of video memory |
